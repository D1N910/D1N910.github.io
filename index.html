AI native 学习笔记法：把笔记从「存信息」改成「存判断」

这段时间在跟 Datawhale 的 All-In-RAG 组队学习，学到第三章的时候突然想明白一件事：我以前做笔记的方式，在 AI 时代基本废了。这篇就写写我现在怎么学、怎么记、怎么验证自己没白学。

0. 先说结论

我说白了，AI native 时代最值钱的不是「记住」，是「判断」。

以前笔记的功能是存信息——老师讲得好、书里写得妙，赶紧抄下来，怕忘了。现在信息随时能生成，解释也几乎不要钱，你抄的那段话问 AI 三秒就能再来一份，甚至讲得比原文清楚。

那笔记还有什么用？我的答案是：存你的判断。存你哪里卡过、哪里猜错过、哪里跟别人的说法不一样。这些东西 AI 生成不出来，因为那是你脑子里长出来的。

瓶颈变了：以前是「找不到资料」，现在是「看懂了，但没长进脑子里」。下面这套方法就是冲着后半句去的。

1. 怎么学：问题驱动，不是章节驱动

旧方式 我现在的方式
从第 1 页读到第 100 页 先抛 3 个问题，带着问题进章节
不懂就从头补基础 卡哪儿补哪儿，AI 当「按需解释器」
看完再动手 先跑通再理解

我第一章就是这么干的：01_langchain_example.py 先跑起来，报错了就查，查完再回头看 RAG 的概念。比起「先学完理论再实践」，这样记得牢得多——因为你是在解决问题的过程中学的，不是在旁观。

具体动作：每开一章之前，先问自己三个问题。比如 index 构建那章，我的问题是「chunk 都切好了，凭什么能搜出来？」「embedding 到底干了什么？」「向量数据库和我在项目里用的 Elasticsearch 有啥区别？」带着这些读，笔记自然有主线，不会变成章节摘抄。

2. 笔记只记四样，其余让 AI 生成

值得记的：

  1. 自己的话。教程说「池化把 token 向量压缩成单一向量」，我口述时说的是「一个 768 维的向量要概括整个文本块，越长越稀释」。后者才是我的，前者是教程的。
  2. 卡住的点 + 怎么爬出来的。我跑示例时遇到三个问题：NLTK 资源被 SSRF 拦截、目录权限太松、API 的 SSL 被掐断。这三个比教程正文值钱十倍，因为下次再踩我能直接翻自己的笔记。
  3. 没搞懂 / 我猜的。学 RAG 简介时我标过「FT 是 finetune 吗」「KB 我猜是类」。后来核实，FT 真是微调，KB 是 Knowledge Base、我猜的「类」其实是它下一层。这种诚实标记是笔记的灵魂——糊过去就假了。
  4. 能直接跑的代码 / 命令。chmod go-w、from unstructured.partition.pdf import partition_pdf，未来我会原样复制。

别记的： 教程原文搬运、AI 的回答原样粘贴、我已经懂的定义。这些随时能再生成，抄一遍只会制造「我学了」的错觉。

MediaPipe + 轻量时序模型：动作识别流水线笔记

这是一篇额外笔记，记录 TFLite、MediaPipe 和轻量时序模型的概念，以及一种可落地的动作识别流水线。与 YOLO26 论文笔记分开，方便以后做健身动作识别项目时直接查。

1. TFLite 推理图、CNN、MediaPipe 图的关系

三者不是同一层概念，不能直接二选一。

概念 是什么 关注点
CNN 模型架构：卷积层、池化、激活、残差怎么连 表达能力、精度
TFLite 推理图 部署产物：转成 .tflite 后的可执行计算图 延迟、内存、算子兼容、量化、GPU/NPU 委托
MediaPipe 图 流水线编排：预处理 → TFLite 推理 → 后处理 整条链路的连接、同步、输入输出

层次关系：

CNN（模型架构）
  → TFLite 图（单个模型的可执行图）
  → MediaPipe 图（整条推理流水线，可能包含多个 TFLite 模型）
  • CNN 是菜谱：描述用什么层、怎么算。
  • TFLite 图是打包好的料理包 + 厨房适配说明：描述在手机上按什么顺序执行哪些算子、张量多大、权重在哪、是否量化。
  • MediaPipe 图是整条厨房流水线：备菜、加热、装盘怎么衔接。

TFLite 图可以装 CNN，也可以装 LSTM、Transformer；CNN 也可以导出成 TFLite 图。所以“TFLite 推理图 vs CNN”不是对立关系，而是部署形态与模型架构的关系。

2. 两段式动作识别流水线

视频帧
→ MediaPipe Pose（每帧检测 33 个关键点）
→ 关键点序列（T×33×4：x, y, z, visibility）
→ 下游时序模型（LSTM / GRU / 1D-CNN / TCN / Transformer）
→ 动作、相位、错误标签
→ 规则映射成指导文案
  • 保留 MediaPipe 做推理：不自己训练姿态模型，继续用 MediaPipe 的预训练姿态模型提取每帧关键点。它内部也是 CNN + TFLite，可以当黑盒用。
  • 下游时序模型：在关键点序列上单独训练一个模型，学习动作随时间的变化。MediaPipe 负责“关节在哪”，时序模型负责“你在做什么动作”。
  • “下游”：MediaPipe 是上游特征提取器，时序模型是下游任务模型。

为什么这么设计

  • 复用成熟的姿态模型，省数据、省训练成本；
  • 关键点维度低，时序模型可以很小，端侧跑得动；
  • 模块化：姿态模型和动作模型可以分别替换、分别调试；
  • 隐私友好：关键点可以在本地处理，不必上传视频。

代价

  • 误差传播：MediaPipe 关键点错了，下游模型跟着错；
  • 丢失外观信息：只看骨架，器械、物体交互看不到；
  • 两段式延迟和集成复杂度；
  • 需要标注动作片段，窗口大小、步长、平滑策略都要调；
  • 遮挡、健身房器械、特殊机位可能让 MediaPipe 失效。

3. 轻量时序模型是什么

它不是只看单帧，而是输入一段时间的特征序列，基于整段序列做判断。
