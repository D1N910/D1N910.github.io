Ultralytics YOLO26: Unified Real-Time End-to-End Vision Models / Ultralytics YOLO26：统一的实时端到端视觉模型

论文阅读笔记

论文信息

  • 标题：Ultralytics YOLO26: Unified Real-Time End-to-End Vision Models
  • 作者：Glenn Jocher、Jing Qiu、Mengyu Liu、Shuai Lyu、Fatih Cagatay Akyon、Muhammet Esat Kalfaoglu（Ultralytics）
  • 发表时间：2026 年 6 月（arXiv:2606.03748v1，2026-06-02）
  • 领域：cs.CV，实时目标检测与统一视觉模型
  • 代码：https://github.com/ultralytics/ultralytics（AGPL-3.0）
  • DOI：10.48550/arXiv.2606.03748

一句话：YOLO26 在 YOLO11 之上，把默认推理路径改成原生端到端、无 NMS 的一对一检测头，同时用双头训练、去 DFL、MuSGD、Progressive Loss 和 STAL 重新平衡精度与部署成本。

摘要

Real-time vision demands models that are accurate, efficient, and simple to deploy across diverse hardware. The YOLO family has become widely deployed for this reason, yet most YOLO detectors still rely on non-maximum suppression at inference, carry heavy detection heads due to Distribution Focal Loss, require long training schedules, and can leave the smallest objects without positive label assignments. We present Ultralytics YOLO26, a unified real-time vision model family that addresses these limitations through coordinated architecture and training advances. Architecturally, YOLO26 uses a dual-head design for native NMS-free end-to-end inference and removes DFL entirely, yielding a lighter head with unconstrained regression range. For training, three techniques jointly improve accuracy while reducing cost: MuSGD, a hybrid Muon–SGD optimizer adapted from large language model training; Progressive Loss, which shifts supervision toward the inference-time head; and STAL, a label assignment strategy that guarantees positive coverage for small objects. Beyond detection, YOLO26 introduces task-specific head and loss designs for instance segmentation, pose estimation, and oriented detection, producing consistent gains across tasks and scales. The family spans five scales (n/s/m/l/x) and supports detection, instance segmentation, pose estimation, classification, and oriented detection in a single pipeline, with an open-vocabulary extension, YOLOE-26, for text-, visual-, and prompt-free inference. Across all scales, YOLO26 achieves 40.9–57.5 mAP on COCO at 1.7–11.8 ms T4 TensorRT latency, advancing the accuracy–latency Pareto front over prior real-time detectors, while YOLOE-26x reaches 40.6 AP on LVIS minival under text prompting. Code and models are available at https://github.com/ultralytics/ultralytics.

实时视觉要求模型在多种硬件上都准确、高效且易于部署。YOLO 家族因此被广泛采用，但大多数 YOLO 检测器在推理时仍依赖非极大值抑制（NMS），因分布焦点损失（DFL）而携带沉重的检测头，需要很长的训练 schedule，并且可能让最小的目标得不到正标签分配。我们提出 Ultralytics YOLO26，一个统一的实时视觉模型家族，通过协同的架构与训练改进来解决这些限制。

架构上，YOLO26 采用双头设计实现原生无 NMS 的端到端推理，并彻底移除 DFL，得到更轻、回归范围不受约束的检测头。训练上，三项技术共同提升精度并降低成本：MuSGD，一种借鉴大语言模型训练的 Muon–SGD 混合优化器；Progressive Loss，把监督逐步移向推理时使用的头；STAL，一种保证小目标正样本覆盖的标签分配策略。

除检测外，YOLO26 还为实例分割、姿态估计和有向检测引入任务专用头与损失设计，在各任务和尺度上带来一致增益。该家族覆盖 n/s/m/l/x 五个尺度，在单一流水线中支持检测、实例分割、姿态估计、分类和有向检测，并提供开放词汇扩展 YOLOE-26，支持文本、视觉和无提示推理。在所有尺度上，YOLO26 在 COCO 上达到 40.9–57.5 mAP，T4 TensorRT 延迟为 1.7–11.8 ms，推进了实时检测器的精度-延迟 Pareto 前沿；YOLOE-26x 在 LVIS minival 文本提示下达到 40.6 AP。代码与模型开源于 https://github.com/ultralytics/ultralytics。

主要内容

1. 研究背景

实时目标检测的长期矛盾是：精度、延迟和部署复杂度很难同时优化。论文把现役 YOLO 检测器的问题归纳为五条：

  1. 推理依赖 NMS。一对多标签分配会让同一个 GT 周围多个 anchor 都成为正样本，推理时产生重复框，必须靠 NMS 去重；NMS 让延迟不确定，也增加部署链路。
  2. YOLOv10 式双头的监督不对称。YOLOv10 已经用双分支实现 NMS-free，但训练时给一对一头和一对多头相同损失权重，导致真正用于推理的一对一头训练不足。
  3. DFL 让检测头变重、回归范围受限。DFL 把每条边的 4 个标量变成 \(4K\) 个 logits（通常 \(K=16\)），并带来有限回归范围。
  4. 训练 schedule 太长。标准 SGD 配方通常需要约 600 个 epoch 才能在 COCO 上达到有竞争力的精度。
  5. TAL 对极小目标零分配。TAL 要求 anchor 中心落在 GT 框内；下采样后，极小目标可能框内一个 anchor 中心都没有，拿到零正样本、零梯度。

YOLO26 的思路不是单点替换，而是同时动架构和训练：双头 + 去 DFL 负责推理路径，MuSGD、Progressive Loss、STAL 负责训练质量。

2. 核心方法

2.1 双头与原生 NMS-free 推理

YOLO26 检测模型有两个头，但训练和推理走不同路径：

  • 一对一头（默认推理）：最多输出 300 个检测，形状为 (N, 300, 6)，即 x1, y1, x2, y2, score, class。它使用 TAL 先取 topk=7 的候选，再用 topk2=1 得到每个 GT 的唯一分配，因此可以直接解码，不需要 NMS。
  • 一对多头（训练辅助 / 可选高精度路径）：保留传统密集输出，形状为 (N, nc+4, 8400)，使用 topk=10 的 TAL 和 NMS。推理时可用 end2end=False 切回这条路径。

训练时两个头都参与，一对多头提供更密集的监督；推理默认只走一对一头。论文把它称为 accuracy–latency knob：要简单、延迟确定，就用一对一头；要极限精度、且平台能高效跑 NMS，就用一对多头。

图 2：共享 backbone 和 neck 同时喂给一对多/一对一头，STAL 改善小目标分配，Progressive Loss 调整两个分支的损失权重，MuSGD 更新参数。来源：arXiv:2606.03748。

2.2 移除 DFL

DFL 把每条边的距离建模成 \(K\) 个 bin 的离散分布：

$$ d=\sum_{i=0}^{K-1} i\cdot \mathrm{softmax}(z)_i,\quad z\in\mathbb{R}^K $$

它有两个代价：

  • 参数/计算膨胀：每条边 1 个标量变成 \(K\) 个 logits，4 条边就是 \(4K\)。YOLO11n 上去掉 DFL 后，参数从 2.6M 降到 2.3M（-12%），GFLOPs 从 6.5 降到 5.2（-20%）；论文还报告头更轻：-0.3M 参数、-1.4 GFLOPs、-0.2 ms。
  • 回归范围有限：每条边的最大可表示距离是 \((K-1)s\)。\(K=16\)、stride 32 时单边约 480 px，宽/高上界约 960 px；1280 分辨率下大目标很容易超过这个范围。

YOLO26 直接去掉 DFL，改成直接框回归 + L1 损失。Table 3 的受控对照显示，去 DFL 在 640 下 +0.3 AP / +1.0 AP_L，在 1280 下 +1.3 AP / +2.2 AP_L；分辨率越高，大目标越容易触到原来的有限范围，收益越明显。

注意 Table 2 和 Table 3 不是同一个实验：Table 2 的“−DFL”是逐步消融中的一步，单步会掉 0.6 AP；Table 3 是在 YOLO26s 配置下控制 DFL 开关的对照。前者说明“先跌”，后者说明“在完整配方下，去 DFL 本身可以是正收益”。

2.3 MuSGD 优化器

MuSGD 是 Muon 与 SGD 的混合优化器：

  • 多维参数（卷积核、线性权重）：使用 Muon 与 SGD 的加权混合。Muon 对动量更新做轻量正交化（几次 Newton–Schulz 迭代），改善更新条件数。
  • 一维参数（bias、归一化层的 scale）：使用纯 SGD，保持 scale/shift 参数稳定。

Table 4 显示，MuSGD 用 500 个 epoch 达到 47.4 mAP，而 SGD 用 600 个 epoch 达到 47.0 mAP，即 +0.4 mAP、少 16.7% 的 epoch。注意这里报的是 epoch，不是 wall-clock；论文没有报告总训练时间或 GPU-hours。

2.4 Progressive Loss

双头训练存在天然的不对称：一对多头监督更密、早期更容易优化；一对一头约束更强，却决定最终推理行为。如果两个头始终等权，推理头会训练不足。

Progressive Loss 用一个随 epoch 线性变化的权重把监督从一对多移向一对一：

$$ \mathcal{L}_{total}=\alpha(t)\mathcal{L}_{one2many}+(1-\alpha(t))\mathcal{L}_{one2one} $$

默认 schedule 是 \((0.8,0.2)\rightarrow(0.1,0.9)\)：一对多权重从 0.8 降到 0.1，一对一头从 0.2 升到 0.9。Table 5 中，等权 baseline 的 E2E AP 是 46.4，最佳 schedule 是 46.7；一开始就用 (1.0, 0.0) 完全压掉一对一头，只有 46.4，说明推理头从训练初期就需要非零监督。

2.5 STAL：小目标感知标签分配

TAL 的候选筛选要求 anchor 中心落在 GT 框内。对极小目标来说，下采样后框内可能没有任何 anchor 中心，于是零正样本、零梯度。

STAL 只改“候选筛选”的几何：对每个 GT，如果某条边 \(d_i\) 小于最小 stride \(s_{min}\)，就在候选筛选时把这条边替换成参考尺寸 \(s_{ref}\)：

$$ \tilde d_i= \begin{cases} s_{ref}, & d_i < s_{min}\\ d_i, & \text{otherwise} \end{cases} $$

当前实现中 \(s_{min}=8\)、\(s_{ref}=16\)（第二层 stride），宽高分别判断。得到的 surrogate box 只用于候选 mask；原始 GT 框仍用于 task-aligned 打分、最终匹配和框回归。这样极小目标至少有一个候选，但不会改变类别，也不会改变回归目标。

Table 6：TAL 46.6 AP / AP_S 29.0；STAL \(s_{ref}=16\) 46.8 AP / AP_S 29.6；\(s_{ref}=8\) 的 AP_S 只有 27.7，\(s_{ref}=32\) 又会扭曲尺度先验，降到 46.5 / 28.3。

2.6 任务头与 YOLOE-26

YOLO26 不是只做检测，它在同一套 backbone/neck 上挂了任务专用头：

  • 实例分割：多尺度 Proto 模块 + 辅助语义分割损失。Table 8 中，YOLO11s 分割 baseline 为 32.0 mAP，多尺度 Proto 升到 32.4，再加辅助损失升到 32.7；相对 YOLO11，box AP 提升 +1.6 到 +2.5，mask AP 提升 +2.4 到 +3.7。
  • 姿态估计：OKS 损失 + RLE（Residual Log-Likelihood Estimation）损失 + 解码优化。Table 9 中 wOKS=24, wRLE=1 最好，63.0 mAP；相对 YOLO11，pose AP 提升 +2.1 到 +7.2。
  • 有向检测（OBB）：改用 \([-45^\circ,135^\circ)\) 的角度定义，并加角度损失处理方形目标的角度不连续。Table 10 中 mAP 从 47.7 升到 49.0；Table 11 中 \(\lambda=3\) 最好，50.2 mAP；相对 YOLO11，OBB mAP 提升 +2.5 到 +3.4，AP75 提升 +4.6 到 +6.0。
  • YOLOE-26：开放词汇扩展，支持文本提示、视觉提示和无提示推理；升级了 YOLO26 检测栈、MobileCLIP2 文本编码器、数据引擎和解耦分割训练。YOLOE-26x 在 LVIS minival 文本提示下达到 40.6 AP。

3. 主要贡献

  1. DFL-free 双头架构：一对一头原生 NMS-free 端到端推理，一对多头保留为可选的高精度密集分支。
  2. 协同训练配方：MuSGD + Progressive Loss + STAL，分别解决长 schedule、训练-推理头不一致、小目标零正样本。
  3. 任务专用头：实例分割、姿态估计、OBB 各有专用头和损失设计，在统一家族内取得一致增益。
  4. YOLOE-26 开放词汇扩展：把文本/视觉/无提示检测接进同一套 YOLO26 检测栈。
  5. 统一家族：n/s/m/l/x 五档，在 COCO 上推进精度-延迟 Pareto 前沿，相对 YOLO11 同尺度提升 1.6–2.8 AP。

4. 实验结果

4.1 实验设置

  • 两阶段训练：Objects365-v1 预训练 150 epoch，再在 COCO 上微调。
  • COCO 微调 epoch：n/s/m/l/x 分别为 245/70/80/60/40，global batch size 128。
  • 评测：COCO val2017；延迟同时报告 CPU ONNX（Intel Xeon 2.00 GHz）和 T4 TensorRT10。

4.3 逐步消融与归因（Table 2）

步骤 NMS AP E2E AP
YOLO11s baseline 47.0 –
− DFL 46.4 –
+ L1 Loss 46.6 –
+ STAL 46.8 –
+ Backbone/neck refinement 47.0 –
+ E2E / Progressive Loss 47.0 46.4 → 46.7
+ MuSGD 47.6 47.1
+ Objects365 pretraining 48.0 47.4
+ Hyperparameter search 48.6 47.8

按 NMS AP 拆，可以粗略归因为：

  • Architecture：−DFL（-0.6）+ backbone/neck refinement（+0.2）= -0.4。
  • Training：+L1（+0.2）+ STAL（+0.2）+ Progressive Loss（+0.2）+ MuSGD（+0.4）= +1.0。
  • Data + HP search：Objects365（+0.4）+ 超参搜索（+0.6）= +1.0。

47.0 − 0.4 + 1.0 + 1.0 = 48.6。这个拆法是按表格顺序累加的，顺序依赖，不是严格的 factorial 归因；但它足够说明：最终增益的大头来自训练配方、预训练数据和调参，而不是单个架构模块。

4.4 关键消融

  • Table 3（去 DFL）：640 下 +0.3 AP / +1.0 AP_L，1280 下 +1.3 AP / +2.2 AP_L。分辨率越高，DFL 的有限范围越容易成为瓶颈。
  • Table 4（MuSGD）：500 epoch 47.4 vs 600 epoch 47.0，+0.4 AP、少 16.7% epoch。它证明的是“更少 epoch 达到更高最终精度”，不等于总 wall-clock 更短。
  • Table 5（Progressive Loss）：等权 46.4 E2E；最佳 (0.8,0.2)→(0.1,0.9) 46.7；(1.0,0.0) 46.4；(0.9,0.1) 46.3。推理头从训练初期就要有监督。
  • Table 6（STAL）：TAL 46.6 / AP_S 29.0；s_ref=16 46.8 / 29.6；8 和 32 都更差。STAL 整体只 +0.2 AP，但 AP_S +0.6，且没有推理成本。

4.5 多任务结果

  • 实例分割：相对 YOLO11，box AP +1.6 到 +2.5，mask AP +2.4 到 +3.7。
  • 姿态估计：相对 YOLO11，pose AP +2.1 到 +7.2；E2E 与 NMS 路径最多差 0.2 AP。
  • OBB：相对 YOLO11，mAP +2.5 到 +3.4，AP75 +4.6 到 +6.0。
  • YOLOE-26x：LVIS minival 文本提示 40.6 AP。

4.6 读实验时要留意的点

  • E2E 与 NMS 的差距是稳定代价，不是训练失败；五档都差 0.6–0.8 AP。
  • DFL 的收益和分辨率强相关，不要在 640 的结果上否定高分辨率下的价值。
  • STAL 的整体 AP 增益很小，但 AP_S 提升更明显；如果业务是小目标密集，不能只看总 AP。
  • MuSGD 报的是 epoch，不是 wall-clock；总训练成本、显存、能耗都没有展开。
  • 超参搜索和 Objects365 的贡献很大，但论文没有披露搜索空间与预算；和其它检测器对比时，要问 baseline 是否拿到同等预训练数据和调参预算。
  • 论文没有报告多次运行的方差/误差棒；单次结果的稳定性需要谨慎看待。

5. 个人思考

  1. 这篇论文的“架构创新”没有叙事里那么重。 Table 2 里 architecture 净贡献约 -0.4，training +1.0，data + HP search +1.0。真正把 48.6 推上去的是训练配方、Objects365 和调参。做项目或写论文时，要分清“模块贡献”和“配方贡献”，不要把所有涨点都算到新模块头上。
  2. 去 DFL 是部署/硬件取舍，不是纯精度胜利。 单步会掉 0.6 AP，但头更轻、回归范围不受限；Table 3 在 1280 下 +1.3 AP / +2.2 AP_L。它更适合高分辨率、大目标、边缘部署的场景，而不是所有场景都无脑去 DFL。
  3. E2E 是部署路径，不是精度路径。 默认一对一头比 NMS 路径低 0.6–0.8 AP，但输出固定、延迟确定、部署简单。工程上要按场景选：要确定性延迟和简单集成，用 E2E；要极限 mAP 且平台能高效跑 NMS，用一对多头。
  4. STAL 的小目标收益真实但窄。 整体 +0.2 AP，AP_S +0.6；没有推理成本。如果业务是小目标密集（无人机、监控、工业缺陷），值得保留；如果只是大中目标，收益有限。MuSGD 省的是 epoch，不是必然的 wall-clock，论文没有报训练总时长。
  5. 论文最强的可能是“统一”，而不是单点。 一套 backbone/neck/heads 覆盖检测、实例分割、姿态、OBB、分类和开放词汇，任务头有一致增益；YOLOE-26 把开放词汇也接进来。这种“家族化”对工程落地比单个模块更有价值；代价是论文对每个模块的归因不够干净，审稿时要盯同预训练、同调参预算。

关键概念速查

概念 一句话解释
NMS 非极大值抑制，按 IoU 和置信度去掉重复框；传统 YOLO 的后处理步骤。
一对一 / 一对多 一对多给一个 GT 多个正样本，需要 NMS；一对一给一个 GT 一个正样本，可直接输出。
DFL 把每条边的距离建模成 K 个 bin 的分布，再用期望解码；精度好但头重、范围有限。
TAL Task-Aligned Learning，按分类与定位的对齐分数选候选 anchor。
STAL 在候选筛选时把极小题的 GT 边临时放宽到 16 px，保证至少有一个候选；原框不变。
MuSGD Muon + SGD 的混合优化器；多维参数用混合更新，1D 参数用纯 SGD。
Progressive Loss 训练中把损失权重从一对多头逐步移向一对一头。
RLE Residual Log-Likelihood Estimation，用残差对数似然估计关键点分布。
mAP vs mAP (E2E) 前者是一对多头 + NMS，后者是一对一头无 NMS；后者通常低 0.6–0.8 AP。
